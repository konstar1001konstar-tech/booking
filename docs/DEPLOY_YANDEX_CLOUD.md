# Как выложить онлайн-запись в Yandex Cloud

Инструкция для владельца сервиса. Писать код не нужно: команды ниже копируются целиком. Делать это удобнее всего в Cloud Shell — чёрное окно в консоли Yandex Cloud в браузере. На компьютер ничего ставить не обязательно.

Сайт после настройки открывается по короткой ссылке мастера, например `https://ваш-адрес/anna`. Заявка клиента сначала записывается в базу в России (регион `ru-central1`), и только потом мастер получает сообщение в Telegram. Токен бота в файлы сайта не кладётся.

Код в репозиторий уже входит. В облако он сам не уезжает: аккаунта Yandex Cloud у сборки нет.

## Что выбрано и почему

- Файлы страницы лежат в Object Storage, но бакет закрыт. Снаружи их отдаёт API Gateway по HTTPS. Так нет отдельной «витрины» бакета, которую можно открыть в обход сайта.
- Одна функция на Node.js обслуживает страницы, заявки, панель мастера и бота. Отдельные функции на каждый адрес здесь только усложнили бы запуск. Node.js выбран потому, что расчёт времени в часовом поясе мастера уже написан на нём и используется и сайтом, и сервером.
- Данные (мастера, заявки, брони слотов, лимиты, одноразовые входы, шаг бота) по умолчанию лежат JSON-объектами в том же закрытом бакете под префиксом `data/` (`storage = "s3"`, переменная функции `STORAGE=s3`). Уникальность слота держит условная запись `If-None-Match: *` в Object Storage. Код для serverless YDB остался и включается `storage = "ydb"`: в ноябре 2026 serverless YDB в этом каталоге отвечал `Query compilation timed out` на любой запрос, поэтому по умолчанию выбран бакет. Секреты — Lockbox. В функцию они попадают как переменные окружения, в git их нет.
- CDN не подключался: для визитки нескольких мастеров лишний кэш и сброс кэша не нужны. Если позже понадобится, его можно поставить перед API Gateway.
- Старые ссылки вида `?config=...` по-прежнему открывают страницу, но заявку на сервер не отправляют. Иначе номер чата мастера снова уходил бы из браузера. Клиенту показывается просьба написать мастеру напрямую.

## Релей Telegram на Vercel

Из Cloud Functions запросы к `api.telegram.org` иногда зависают. Поэтому функция может звать Telegram через маленький релей на Vercel: `api/tg/[method].js` в этом же репозитории. Vercel сам выкладывает ветку `main` на `https://booking-dun-beta.vercel.app`, статическая страница там работает как раньше.

- `POST https://booking-dun-beta.vercel.app/api/tg/<метод>` пересылается в `https://api.telegram.org/bot<токен>/<метод>` и возвращает ответ Telegram как есть.
- Токен бота приходит в заголовке `X-Bot-Token`, в коде релея и в Vercel его нет.
- Чужие запросы отсекаются ключом в заголовке `X-Relay-Key`. В файле лежит только SHA-256 ключа, сам ключ хранится в Lockbox под именем `relay_key`.
- Имя метода — только латинские буквы.

Включается строкой `relay_url = "https://booking-dun-beta.vercel.app/api/tg"` в `terraform.tfvars`. Без неё функция ходит в Telegram напрямую. Новый ключ релея: сгенерируйте строку (`openssl rand -hex 32`), положите её в Lockbox как `relay_key`, а её SHA-256 (`printf %s 'ключ' | sha256sum`) — в `RELAY_KEY_SHA256` в `api/tg/[method].js`, закоммитьте и выполните `terraform apply` с id новой версии секрета.

**Адреса Vercel.** Из Yandex Cloud новые IP Vercel (`216.198.79.x`, `64.29.17.x`, которые DNS отдаёт для `*.vercel.app`) часто не отвечают: соединение не открывается или зависает TLS-рукопожатие, независимо от имени хоста. Старый anycast-адрес Vercel `76.76.21.21` работает стабильно, поэтому функция подключается к релею по нему (переменная `relay_ips`, по умолчанию `76.76.21.21`; имя хоста остаётся для TLS и `Host`). Если и он перестанет отвечать, впишите другой адрес или оставьте `relay_ips = ""` — тогда обычный DNS. Проверить сеть из функции: `yc serverless function invoke booking-api -d '{"diag":"relay"}'` — вернёт тайминги до каждого IP (без секретов).

**Outbox.** Заявка ждёт ответа Telegram не больше 4 секунд. Если релей не ответил, уведомление сохраняется в `data/outbox/<id>.json`, клиент сразу получает ответ, а таймер `booking-outbox` (раз в минуту) досылает сообщение: повторы с паузой 1, 2, 4… до 30 минут, через 24 часа запись удаляется. После отправки в заявку записывается id сообщения. Так же досылаются ответы бота (ссылки для входа — не дольше 9 минут, пока они действуют).

## Сколько это стоит

Бесплатный объём считается на весь платёжный аккаунт и сгорает в конце месяца. Цифры ниже — с документации Yandex Cloud, страница [бесплатного уровня serverless](https://yandex.cloud/ru/docs/billing/concepts/serverless-free-tier). Перед оплатой откройте её ещё раз: прайс меняется.

Каждый месяц не тарифицируются, пока вы в этих пределах:

- Cloud Functions: 1 000 000 вызовов и 10 ГБ·час работы.
- API Gateway: первые 100 000 запросов.
- YDB serverless (только при `storage = "ydb"`): первые 1 000 000 единиц запроса (Request Units) и первый 1 ГБ хранения.
- Object Storage, стандартное хранилище: первый 1 ГБ, 10 000 операций записи и 100 000 операций чтения.

При хранении в бакете каждая заявка — около 3–5 записей и 5–10 чтений, каждый показ страницы мастера — 2–3 чтения. Для нескольких мастеров и обычного потока заявок этого хватает. Vercel-релей укладывается в бесплатный план Hobby. Платёжный аккаунт и карта всё равно нужны: без них облако не включается, даже если по факту вы останетесь в бесплатном объёме.

Отдельно могут считаться исходящий трафик, свой домен у регистратора и DNS, если зону держите в Yandex Cloud. Управляемый сертификат смотрите в прайсе Certificate Manager, не закладывайте чужую сумму. Калькулятор: [yandex.cloud/ru/prices](https://yandex.cloud/ru/prices).

## 1. Каталог

1. Зарегистрируйтесь на [console.yandex.cloud](https://console.yandex.cloud) как частное лицо.
2. Привяжите платёжный аккаунт.
3. Создайте каталог, например `booking`. Дальше все ресурсы должны быть в нём, регион `ru-central1` (Россия).
4. Справа сверху откройте Cloud Shell.

В Cloud Shell уже есть команда `yc`, и вы в ней залогинены. Проверьте каталог:

```sh
yc config list
```

Если каталог не тот:

```sh
yc config set folder-id <id каталога>
```

Id каталога виден в адресной строке консоли и в карточке каталога.

## 2. Бот в Telegram

1. В Telegram откройте `@BotFather`.
2. Отправьте `/newbot`.
3. Задайте имя, которое видят люди, и имя бота, которое кончается на `bot`.
4. BotFather пришлёт токен. Он выглядит как `123456789:AAH...`.
5. Скопируйте его в черновик заметки на телефоне. В файлы проекта, в чат и в скриншоты его не кладите. После шага 4 заметку можно стереть: токен останется только в Lockbox.

Пока секрет в облаке ещё не создан. Токен понадобится на шаге 5.

## 3. Скачать проект

В Cloud Shell:

```sh
git clone https://github.com/konstar1001konstar-tech/booking.git
cd booking
```

Если эта инструкция ещё не в ветке `main`, переключитесь на ветку, где она лежит:

```sh
git checkout cursor/yandex-cloud-multitenant-8460
```

Поставьте Terraform, если команда `terraform version` пишет, что программы нет. Способ установки — в официальной статье [Начало работы с Terraform](https://yandex.cloud/ru/docs/tutorials/infrastructure-management/terraform-quickstart). Нужна версия 1.5 или новее.

Подготовьте вход в Terraform. Токен живёт около 12 часов. Если установка идёт долго и команды начинают отвечать «unauthorized», выполните эти три строки ещё раз.

```sh
export YC_TOKEN=$(yc iam create-token)
export YC_CLOUD_ID=$(yc config get cloud-id)
export YC_FOLDER_ID=$(yc config get folder-id)
```

Соберите архив функции. Внутри нет секретов и нет `node_modules`: облако само поставит библиотеку базы, когда создаст версию функции.

```sh
sh scripts/package-function.sh
```

Если напишет, что нет `zip`, в обычном Linux это `sudo apt-get install -y zip`. В Cloud Shell `zip` обычно уже есть.

## 4. Первый запуск Terraform

```sh
cd infra/terraform
cp terraform.tfvars.example terraform.tfvars
```

Откройте `terraform.tfvars` и замените только имя бакета на своё. Имя должно быть уникальным во всём Yandex Cloud, маленькими латинскими буквами, например `booking-card-ivanova`. Остальное оставьте как в примере: `deploy_function = false`.

Файл `terraform.tfvars` в git не попадает. Не переименовывайте его в файл, который можно закоммитить.

```sh
terraform init
terraform apply
```

На вопрос введите `yes`.

Этот запуск создаёт каталожные вещи без сайта: закрытый бакет, базу YDB и пустой секрет Lockbox, сервисные аккаунты и таблицы. Функции ещё нет — для неё нужен секрет.

Если бакет ругается на доступ, подождите минуту и выполните `terraform apply` ещё раз: право сервисного аккаунта иногда догоняет не сразу.

## 5. Секрет в Lockbox, только через консоль

1. В консоли откройте Lockbox.
2. Откройте секрет `booking-secrets`.
3. Нажмите создание новой версии.
4. Добавьте три ключа. Имена ключей копируйте точно, значения — нет.

| Ключ | Значение |
| --- | --- |
| `bot_token` | токен из BotFather |
| `session_secret` | длинная случайная строка |
| `webhook_secret` | другая длинная случайная строка |
| `relay_key` | только если включён релей Telegram, см. выше |

Случайные строки получите в Cloud Shell и вставьте в форму. В файл их не сохраняйте:

```sh
openssl rand -hex 32
openssl rand -hex 32
```

5. Сохраните версию.
6. Откройте созданную версию и скопируйте её id. Это не сам токен.

В `infra/terraform/terraform.tfvars` допишите id и включите функцию:

```
deploy_function    = true
lockbox_version_id = "сюда id версии"
set_webhook        = true
```

`public_url` оставьте пустым. Адрес шлюза появится только после следующего запуска, а вебхук функция зарегистрирует сама, когда вы откроете проверку здоровья.

Снова:

```sh
export YC_TOKEN=$(yc iam create-token)
cd ~/booking/infra/terraform
terraform apply
```

В конце будет адрес вида `d5d........apigw.yandexcloud.net`. Сайт: `https://` плюс этот адрес.

## 6. Загрузить файлы страницы

Нужна программа `aws` или `yc`. В Cloud Shell обычно есть `yc`. Из каталога `infra/terraform`:

```sh
sh ../../scripts/upload-static.sh
```

Скрипт сам берёт ключ бакета из Terraform. Ключ секретный: он лежит в `terraform.tfstate` на этой машине. Файл state никуда не отправляйте и в git не кладите. В переписку ключ не копируйте.

Загружаются `app.js`, `styles.css`, `calendar.js`, иконки и `robots.txt`. Сам `index.html` в бакет для показа не нужен: страницу с заголовками для соцсетей собирает функция. Поэтому после правки страницы архив функции тоже нужно пересобрать (шаг 11).

## 7. Подключить бота

Откройте в браузере:

```text
https://АДРЕС-ИЗ-ВЫВОДА/api/health
```

Должно быть примерно так: `{"ok":true,"webhook":"set"}`.

- `skipped` — в `terraform.tfvars` не стоит `set_webhook = true`, или не заданы секрет вебхука и токен.
- `error` — токен или секрет вебхука в Lockbox неверные. Новую версию секрета создают в консоли, id версии меняют в `terraform.tfvars`, затем снова `terraform apply`.

Напишите своему боту `/start`. Он попросит короткий адрес латиницей, например `anna-nails`. Адрес потом не меняется: это часть ссылки. Затем бот пришлёт:

- ссылку для клиентов, вида `https://адрес/anna-nails`;
- одноразовую ссылку входа в настройки. Она живёт 10 минут и сгорает после открытия.

По ссылке входа заполните имя, услуги, дни и часы и нажмите «Сохранить профиль». После этого клиентская ссылка начинает принимать заявки. Пока профиль не сохранён, посторонний видит текст «Страница ещё готовится».

Проверка: откройте клиентскую ссылку с телефона, отправьте пробную заявку. В Telegram у мастера должно прийти сообщение с кнопками «Подтвердить» и «Отменить». Та же заявка видна в панели. Занятое время пропадает из свободных окон.

## 8. Свой домен и HTTPS

Без своего домена сайт уже открывается по HTTPS на адресе `*.apigw.yandexcloud.net`. Этого достаточно, чтобы пользоваться записью.

Когда будет домен:

1. В `terraform.tfvars` впишите `domain = "zapis.example.ru"`. Пока не применяйте, если не готовы подождать выпуск сертификата.
2. `terraform apply`. Появится сертификат Certificate Manager со способом проверки DNS CNAME.
3. В консоли откройте Certificate Manager, сертификат `booking-cert`, и скопируйте имя и значение CNAME.
4. У регистратора домена создайте эту CNAME-запись. Пока статус сертификата не станет «Выпущен», привязка домена к шлюзу может падать. Тогда подождите и повторите `terraform apply`.
5. В DNS домена создайте запись, которую покажет консоль у API Gateway для своего домена (обычно CNAME на адрес `*.apigw.yandexcloud.net`).
6. Когда сайт открывается по домену, снова откройте `https://zapis.example.ru/api/health`, чтобы бот слал ссылки уже на домен. Если вебхук уже ставился на старый адрес, в `terraform.tfvars` временно можно оставить `set_webhook = true` и открыть health именно с нового домена. Функция запоминает регистрацию в рамках одного запуска; если `webhook` уже `skipped`, поставьте новую версию функции ещё одним `terraform apply` и откройте health снова.

В `public_url` можно вписать `https://zapis.example.ru` без слэша в конце, если хотите, чтобы ссылки в боте всегда были на домен, даже когда health открывают со старого адреса.

## 9. Как устроены роли

Отдельным людям права выдавать не нужно. Сервисные аккаунты такие:

- `booking-functions` — `storage.editor` только на этот бакет (данные в `data/`), `ydb.editor` только на эту базу и `lockbox.payloadViewer` только на этот секрет. К бакету функция ходит IAM-токеном своего сервисного аккаунта, статических ключей у неё нет. Функцию снаружи напрямую не открывают.
- `booking-gateway` — `serverless.functions.invoker` только на эту функцию и `storage.viewer` только на этот бакет. Шлюз отдаёт из бакета только перечисленные в `api/openapi.yaml` файлы, `data/` наружу не попадает.
- `booking-deploy` — `storage.admin` на каталог. Он нужен, чтобы Terraform и скрипт загрузки могли писать файлы. На сайт от его имени посетители не ходят.

## 10. Первый мастер, коротко

1. Мастер открывает бота и отправляет `/start`.
2. Присылает адрес латиницей, 3–32 символа, без дефиса по краям. `admin` и `api` заняты сайтом.
3. Открывает одноразовую ссылку из ответа бота.
4. Заполняет услуги и график, сохраняет.
5. Копирует короткую ссылку и ставит её в шапку профиля.

Дальше `/start` или `/link` снова присылают ссылку для клиентов и новую ссылку входа. Вход через виджет Telegram на странице не выведен: домен бота в BotFather для него не нужен. Проверка подписи виджета на сервере есть, если виджет добавите позже (`POST /api/admin/telegram-widget`).

Кнопки в Telegram и кнопки в панели ставят один и тот же статус заявки. «Удалить» стирает заявку из базы. «Отменить» оставляет её в списке со статусом «Отменена» и снова открывает время.

Лимит заявок: 10 с одного адреса за 10 минут и 5 с одного телефона за час, считая отдельно по каждому мастеру. Это защита от пачки заявок, не капча.

## 11. Как обновить сайт потом

После правки страницы или функции:

```sh
cd ~/booking
git pull
sh scripts/package-function.sh
export YC_TOKEN=$(yc iam create-token)
cd infra/terraform
terraform apply
sh ../../scripts/upload-static.sh
```

`terraform apply` нужен, когда менялась функция или `index.html` внутри архива. Если менялись только `app.js` или `styles.css`, достаточно скрипта загрузки. Кэш статики — около пяти минут.

## Чего не делать

- Не вставляйте токен бота, `session_secret` и `webhook_secret` в код, в `terraform.tfvars` и в коммит. В `terraform.tfvars` лежит только id версии Lockbox.
- Не меняйте `scripts/upload-static.sh` на синхронизацию с удалением (`--delete`): в бакете под `data/` лежат заявки.
- Не отправляйте никому `terraform.tfstate`: в нём есть ключ бакета.
- Не включайте публичный доступ к бакету. Сайт и так открывается через API Gateway.
- Не пишите клиентам старые ссылки `?config=`. Новым мастерам нужна короткая ссылка.

## Если что-то не так

- `webhook: error` — проверьте ключи (`bot_token`, `session_secret`, `webhook_secret`, при релее `relay_key`) в последней версии Lockbox и что в `terraform.tfvars` указан id именно этой версии.
- Страница мастера без стилей — не выполнился `scripts/upload-static.sh` или бакет другой.
- Бот молчит — откройте `/api/health` и посмотрите `webhook`. В BotFather токен должен совпадать с `bot_token`.
- «Слишком много заявок» — подождите час или попробуйте с другого телефона. Это лимит, не поломка.
- Заявка в панели есть, а в Telegram нет — запись в базе уже сделана. Проверьте токен и что мастер нажал `/start` у этого бота. Повторно слать ту же заявку не нужно: слот уже занят.

Удаление всего каталога ресурсов: в `infra/terraform` команда `terraform destroy`. Она сотрёт базу заявок и файлы. Для обычной работы она не нужна.
